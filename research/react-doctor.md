# React Doctor: what it is and what a 100/100 score takes

Researched 2026-11-07. Sources are primary only: the [millionco/react-doctor](https://github.com/millionco/react-doctor) repo and its source, the npm registry entry, the docs at react.doctor, and the repo's issue tracker. Source links point at commit [`9791c32`](https://github.com/millionco/react-doctor/tree/9791c32f61fb1477a4f8dd596ff80184ad26b2e3) (2026-11-01), which is the source of the `0.9.22` release.


## Summary

React Doctor is real. It is an open-source CLI from Million Software (the Million.js team, lead maintainer Aiden Bai). It statically scans a React codebase for problems and prints a 0–100 health score. The rule checks run locally, but the score does not. **The CLI sends the list of findings to `https://www.react.doctor/api/score`, and the server computes the score.** The scoring formula is not in the open-source code, and the maintainer has said it changes often. This affects how you can use "100/100" as a quality gate.

### Constraints for the stack decision

- **Stack fit is good.** Plain client-side React on Vite is a first-class framework target, and TS/TSX and JS/JSX are both scanned. Monorepos are supported, with a separate score per project. The Express + Socket.IO server is not a React project. Keep it out of the scan with `--project`, `projects`, or `ignore.files`.
- **The score needs the network and sends metadata out.** Each scored run POSTs every diagnostic to react.doctor: rule, message, line and column, and the file path with sensitive parts scrubbed. It also sends the repo identity from the git `origin` remote, the HEAD SHA, the framework, the React version and the source-file count. No account or API key is needed. File contents are not sent, according to the Data Use page. With `--no-score` or offline, **you get no score at all, and the CLI does not fall back to a local score.**
- **Some default checks also use the network.** The supply-chain check queries Socket.dev for every direct dependency, dev dependencies included. Any dependency that scores below 50 on Socket's supply-chain or vulnerability axis produces an **error**, which counts against the score. Your dependency choices (Socket.IO client, UI libraries, and so on) therefore affect the score. You can turn this off with `supplyChain.enabled: false` or `--no-supply-chain`.
- **The score is reproducible only for a fixed scanner version and a fixed server formula.** The diagnostics are deterministic. The score formula on the server is not versioned in the repo and changes over time. The same commit could score differently later. Pin the scanner version, for example `react-doctor@0.9.22`, not `@latest`.
- **License.** The code is under a "Modified MIT" license, even though the README calls it MIT. Using the software as **AI training, fine-tuning or evaluation data**, or as input to an ML-improvement pipeline, requires written permission. So does reselling it as a hosted service. Normal use as a dev tool on your own code is unaffected.
- **Runtime requirement.** Node `^20.19.0 || >=22.13.0`.

### How to gate on it

- **Exit codes depend on finding severity, not on the score.** `--blocking error` is the CLI default and exits 1 on any error-level finding. `--blocking warning` exits 1 on any finding at all. `--blocking none` always exits 0. There is **no `--fail-under` or score-threshold flag** in the CLI or in the GitHub Action.
- The closest local, deterministic equivalent of "100/100" is **zero findings on the `ciFailure` surface**: `npx react-doctor@0.9.22 --blocking warning -y`. This works offline with `--no-score`. Whether zero findings always produces exactly 100 is not documented. The docs do show a clean PR scan reported as "100/100 (Great)".
- To check the literal score, use `--score`, which prints only the number, or `--json`, which puts it in `.summary.score`. Fail if the value is not `100` **and also if it is empty or null**. The score is `null` when the API is unreachable, and `--score` mode always exits 0.
- **GitHub Action:** `millionco/react-doctor@v2`, with input `blocking: warning` and `scope: full`. It exposes `score`, `error-count` and `warning-count` as outputs, so a follow-up step can assert `score == 100`. The Action defaults to advisory mode (`blocking: none`), and **push events never fail**.
- **Pre-commit:** `--staged` scans only staged files. `npx react-doctor install` can register a hook with simple-git-hooks, Lefthook, and similar tools.
- **Two recommended setups.**
  1. A strict gate: `--blocking warning --no-score`. It is deterministic, works offline and sends nothing.
  2. An informational score: a separate pinned `--score` step, not a merge gate. Use this one only if you accept the network dependency and the upload.

### Network, accounts and data

- **No account or API key is needed** for the CLI. Nothing in the install or run docs mentions logging in ([Quickstart](https://www.react.doctor/docs/overview/quickstart.md)). The Socket.dev lookup uses Socket's "keyless, no-API-token endpoint" ([constants.ts L900–909](https://github.com/millionco/react-doctor/blob/9791c32f61fb1477a4f8dd596ff80184ad26b2e3/packages/core/src/constants.ts#L900-L909)).
- **The score is computed remotely.** `SCORE_API_URL = "https://www.react.doctor/api/score"` ([constants.ts L164](https://github.com/millionco/react-doctor/blob/9791c32f61fb1477a4f8dd596ff80184ad26b2e3/packages/core/src/constants.ts#L164)). `requestScore` POSTs a gzipped JSON body ([request-score.ts L119–](https://github.com/millionco/react-doctor/blob/9791c32f61fb1477a4f8dd596ff80184ad26b2e3/packages/core/src/request-score.ts#L119)) that contains:
  - every diagnostic, minus a few internal fields, with `filePath` passed through `scrubSensitivePaths` and `redactSensitiveText` ([L44–56](https://github.com/millionco/react-doctor/blob/9791c32f61fb1477a4f8dd596ff80184ad26b2e3/packages/core/src/request-score.ts#L44-L56)). Diagnostics include rule, severity, category, message, help, line, column, offset and length ([types/diagnostic.ts](https://github.com/millionco/react-doctor/blob/9791c32f61fb1477a4f8dd596ff80184ad26b2e3/packages/core/src/types/diagnostic.ts));
  - metadata: `repo`, `sha`, `framework`, `reactVersion`, `sourceFileCount`, `defaultBranch`, `doctorVersion`, `runId`, plus GitHub event, actor-association and viewer-permission fields in CI ([request-score.ts L64–85](https://github.com/millionco/react-doctor/blob/9791c32f61fb1477a4f8dd596ff80184ad26b2e3/packages/core/src/request-score.ts#L64-L85), assembled in [run-inspect.ts L854–867](https://github.com/millionco/react-doctor/blob/9791c32f61fb1477a4f8dd596ff80184ad26b2e3/packages/core/src/run-inspect.ts#L854-L867)). `repo` comes from `remote.origin.url` and `sha` from HEAD ([create-git-repository-metadata-cache.ts](https://github.com/millionco/react-doctor/blob/9791c32f61fb1477a4f8dd596ff80184ad26b2e3/packages/core/src/utils/create-git-repository-metadata-cache.ts)).
- If the API is unreachable, the score is `null` and the CLI prints "Score unavailable (could not reach the score API)" ([build-no-score-message.ts](https://github.com/millionco/react-doctor/blob/9791c32f61fb1477a4f8dd596ff80184ad26b2e3/packages/react-doctor/src/cli/utils/build-no-score-message.ts)).
- The maintainer confirmed in an issue that local score calculation was removed on purpose: "we removed it because scoring is something we tweak pretty frequently right now … the scoring methodology can change as we fix false positives, reweight issues … we currently prefer no score over a bad score." An enterprise option was offered for strict environments ([issue #730](https://github.com/millionco/react-doctor/issues/730)). Older versions had an `--offline` flag and briefly a local score ([issue #89](https://github.com/millionco/react-doctor/issues/89), [CHANGELOG](https://github.com/millionco/react-doctor/blob/9791c32f61fb1477a4f8dd596ff80184ad26b2e3/packages/react-doctor/CHANGELOG.md)).
- **Telemetry:** "The CLI collects crash reports and anonymous usage data", which can be turned off with `--no-telemetry` ([README](https://github.com/millionco/react-doctor/blob/9791c32f61fb1477a4f8dd596ff80184ad26b2e3/README.md)). The Data Use page says crash reports go to Sentry and traces and metrics go to Axiom over OTLP. The telemetry includes rule names, counts, the score and timings. The page says "The CLI does not send your file contents or code snippets" ([Data Use](https://www.react.doctor/docs/legal/data-use)). The Data Use page does not describe the score-API payload, so the source code is the authoritative description of it.
- **Opt-out:** `--no-score`, with alias `--no-telemetry`, "skip[s] the score API, the share URL, and crash reporting" ([cli/index.ts L248](https://github.com/millionco/react-doctor/blob/9791c32f61fb1477a4f8dd596ff80184ad26b2e3/packages/react-doctor/src/cli/index.ts#L248)). The config key `noScore: true` does the same ([Config files](https://www.react.doctor/docs/configuration/config-files.md)). **Known gap:** the env var `REACT_DOCTOR_NO_TELEMETRY=1` turns off Sentry and Axiom but *not* the score upload. Only the flag does. This is open issue [#1829](https://github.com/millionco/react-doctor/issues/1829), reported against 0.9.14. I have not verified whether 0.9.22 fixes it, so treat it as **unconfirmed fixed**.
- **Supply chain:** the scanner calls `https://firewall-api.socket.dev/purl/...` for each direct dependency by default ([constants.ts L909](https://github.com/millionco/react-doctor/blob/9791c32f61fb1477a4f8dd596ff80184ad26b2e3/packages/core/src/constants.ts#L909)). Turn it off with `--no-supply-chain` or `supplyChain.enabled: false`.
- **Separate hosted product:** a GitHub-app PR review downloads repo tarballs into a Vercel Sandbox for analysis ([Data Use](https://www.react.doctor/docs/legal/data-use)). The CLI and the Action do not need it.

## 2. How the score is computed

- **Categories.** The config docs list five severity buckets: `Security`, `Bugs`, `Performance`, `Accessibility`, `Maintainability` ([Config files](https://www.react.doctor/docs/configuration/config-files.md)). The rule index is finer-grained. It reports "802 active rules and 6 retired compatibility entries" under these headings: Accessibility, Architecture, Bugs, Bundle Size, Correctness, Design, Maintainability, Next.js, Performance, Preact, React Compiler, React Native, Security, Server, State & Effects, TanStack Query, TanStack Start ([rules index](https://www.react.doctor/prompts/rules.md)). Rules turn on according to detected capabilities (framework, React version, Tailwind and so on), so a Vite SPA does not get the Next.js or React Native rules ([capabilities.ts](https://github.com/millionco/react-doctor/blob/9791c32f61fb1477a4f8dd596ff80184ad26b2e3/packages/core/src/project-info/capabilities.ts)).
- **Default checks** are curated lint rules, React complexity analysis (`no-high-complexity-react-function`, which flags cyclomatic or cognitive complexity above 15), JSX duplication (`duplicate-jsx-subtree`), and the Socket.dev supply-chain check. Dead-code and graph rules (`unused-file`, `unused-export`, `unused-type`, `unused-dependency`, `unused-dev-dependency`, `circular-dependency`) are **off by default** and run only on full scans ([React Maintainability](https://www.react.doctor/docs/overview/react-maintainability.md)).
- **What goes into the score.** Diagnostics on the `score` surface. By default this drops `design`-tagged rules ([diagnostic-surface.ts](https://github.com/millionco/react-doctor/blob/9791c32f61fb1477a4f8dd596ff80184ad26b2e3/packages/core/src/diagnostic-surface.ts)) and findings in test and story files ([Config files](https://www.react.doctor/docs/configuration/config-files.md)). If lint or maintainability analysis did not finish, the score is `null` instead of an overstated number ([run-inspect.ts L874–885](https://github.com/millionco/react-doctor/blob/9791c32f61fb1477a4f8dd596ff80184ad26b2e3/packages/core/src/run-inspect.ts#L874-L885)).
- **Weighting is not public.** The client sends diagnostics and gets back `{ score, label, rules?: { [rule]: { priority, tier: "P0"|"P1"|"P2"|"P3" } } }` ([request-score.ts L27–37](https://github.com/millionco/react-doctor/blob/9791c32f61fb1477a4f8dd596ff80184ad26b2e3/packages/core/src/request-score.ts#L27-L37)). The per-rule priority tiers come from the server, and the CLI uses them to rank diagnostics ([CHANGELOG, PR #596](https://github.com/millionco/react-doctor/blob/9791c32f61fb1477a4f8dd596ff80184ad26b2e3/packages/react-doctor/CHANGELOG.md)). The formula itself (penalty per error or warning, whether it scales with `sourceFileCount`, and so on) is **unconfirmed / not published**. The claim that "errors weigh more than warnings" appears only in secondary write-ups. It is not in a primary source, so treat it as unconfirmed.
- **Labels** (client constants): `PERFECT_SCORE = 100`, "good" threshold at 75 or above, "ok" at 50 or above ([constants.ts L156–160](https://github.com/millionco/react-doctor/blob/9791c32f61fb1477a4f8dd596ff80184ad26b2e3/packages/core/src/constants.ts#L156-L160)). The Node API docs show a label of `"Great"` for a score of 82 ([Node.js API](https://www.react.doctor/docs/reference/node-api.md)).
- **Determinism.** Diagnostic output is deterministic. The changelog says "two runs of the same repo produce byte-[identical]" output (PR #903), and diagnostic IDs are deterministic as well ([CHANGELOG](https://github.com/millionco/react-doctor/blob/9791c32f61fb1477a4f8dd596ff80184ad26b2e3/packages/react-doctor/CHANGELOG.md), [json-report.md](https://github.com/millionco/react-doctor/blob/9791c32f61fb1477a4f8dd596ff80184ad26b2e3/docs/json-report.md)). **The score is deterministic only for a fixed server formula.** The maintainer says it is tweaked frequently ([#730](https://github.com/millionco/react-doctor/issues/730)), and the CLI cannot compute it offline. Rule sets also change between releases.
- **Score scope.** The score covers what was scanned. A PR-scope scan with no findings was reported as "100/100 (Great)" ([GitHub Actions setup](https://www.react.doctor/docs/ci-and-prs/github-actions-setup.md)). In a monorepo the overall result is the worst project's score ([CLI reference](https://www.react.doctor/docs/reference/cli-reference.md), [build-json-report.ts](https://github.com/millionco/react-doctor/blob/9791c32f61fb1477a4f8dd596ff80184ad26b2e3/packages/core/src/build-json-report.ts)).

## 3. Supported stack

- **Frameworks:** Next.js, Vite, Astro, TanStack, React Native and Expo ([README](https://github.com/millionco/react-doctor/blob/9791c32f61fb1477a4f8dd596ff80184ad26b2e3/README.md)), and Preact ([What is React Doctor?](https://www.react.doctor/docs/overview/what-is-react-doctor.md)). The detector also recognises Remix, Gatsby and CRA (`react-scripts`). A project with `react` but no known framework is labelled plain "React" ([detect-framework.ts](https://github.com/millionco/react-doctor/blob/9791c32f61fb1477a4f8dd596ff80184ad26b2e3/packages/core/src/project-info/detect-framework.ts)). A project needs `react` in dependencies or peerDependencies, or the scan fails with "No React dependency found" ([project-info/errors.ts](https://github.com/millionco/react-doctor/blob/9791c32f61fb1477a4f8dd596ff80184ad26b2e3/packages/core/src/project-info/errors.ts)). That means **a Vite + React client works directly**, and the Express/Socket.IO server package will not be treated as a React project.
- **React versions:** no minimum version is documented. Version-gated rules use a capability ladder starting at React 17 (`EARLIEST_GATED_REACT_MAJOR = 17`, [constants.ts L60](https://github.com/millionco/react-doctor/blob/9791c32f61fb1477a4f8dd596ff80184ad26b2e3/packages/core/src/constants.ts#L60)), with extra gates such as `react:19.2` for `<Activity>` ([capabilities.ts](https://github.com/millionco/react-doctor/blob/9791c32f61fb1477a4f8dd596ff80184ad26b2e3/packages/core/src/project-info/capabilities.ts)). Official support for React 16 or lower is **unconfirmed**.
- **JS vs TS:** both. The maintainability passes match `\.[cm]?[jt]sx?$` ([constants.ts L1043](https://github.com/millionco/react-doctor/blob/9791c32f61fb1477a4f8dd596ff80184ad26b2e3/packages/core/src/constants.ts#L1043)), and contextual scoping "supports JavaScript, TypeScript, JSX, and TSX" ([CLI reference](https://www.react.doctor/docs/reference/cli-reference.md)). The package depends on `typescript >=5.0.4 <6` ([npm](https://registry.npmjs.org/react-doctor)).
- **Monorepos:** yes. `--project` takes workspace names or directory paths, and `"*"` selects every project. There is a `projects` config key, per-project config layered on the root config, and one score per project plus a worst-of total ([CLI reference](https://www.react.doctor/docs/reference/cli-reference.md), [Config files](https://www.react.doctor/docs/configuration/config-files.md)). The Action has `directory` and `project` inputs ([action.yml](https://github.com/millionco/react-doctor/blob/9791c32f61fb1477a4f8dd596ff80184ad26b2e3/action.yml)).
- It also adopts existing JSON ESLint or oxlint config by default (`adoptExistingLintConfig: true`). Those adopted rules' findings also become diagnostics ([Config files](https://www.react.doctor/docs/configuration/config-files.md)).

## 4. Configurability

All of the following comes from [Config files](https://www.react.doctor/docs/configuration/config-files.md) unless another source is linked.

- **Disable rules:** `rules: { "<rule>": "off" }`, `categories: { Performance: "off" }`, `ignore.tags: ["design"]`, or the CLI (`rules disable <rule>`, `rules category <Cat> off`).
- **Run but drop findings:** `ignore.rules`, or per-file `ignore.overrides: [{ files, rules }]`.
- **Exclude files:** `ignore.files: ["src/generated/**"]`. Generated or vendored files marked in `.gitattributes` (linguist) are also excluded ([CHANGELOG PR #1549](https://github.com/millionco/react-doctor/blob/9791c32f61fb1477a4f8dd596ff80184ad26b2e3/packages/react-doctor/CHANGELOG.md)).
- **Inline:** `// react-doctor-disable-next-line react-doctor/<rule>`, with comma-separated rule names for several rules ([How to fix issues](https://www.react.doctor/docs/getting-started/how-to-fix-issues.md)). `respectInlineDisables` is true by default. `--no-respect-inline-disables` is an audit mode that ignores suppressions ([cli/index.ts](https://github.com/millionco/react-doctor/blob/9791c32f61fb1477a4f8dd596ff80184ad26b2e3/packages/react-doctor/src/cli/index.ts)).
- **Score-specific:** `surfaces.score` accepts `includeTags`, `excludeTags`, `excludeCategories`, `includeRules` and `excludeRules` ([types/config.ts L131–159](https://github.com/millionco/react-doctor/blob/9791c32f61fb1477a4f8dd596ff80184ad26b2e3/packages/core/src/types/config.ts#L131-L159)). This lets a finding stay visible in the CLI while being dropped from the score or the CI gate.
- **Does that still give 100/100?** As far as the mechanics go, yes. Config overrides, ignores and surface exclusions are applied before the diagnostics are sent to the score API ([run-inspect.ts L869–885](https://github.com/millionco/react-doctor/blob/9791c32f61fb1477a4f8dd596ff80184ad26b2e3/packages/core/src/run-inspect.ts#L869-L885)). The tool does not record or penalise suppressions, so a "100/100" can be reached by configuration alone. Nothing in the docs or source says the server penalises suppression counts (**unconfirmed**; the payload does not include a suppression count). For a meaningful gate, also review `doctor.config.*` and grep for `react-doctor-disable`. You can also run an audit with `--no-respect-inline-disables`.

## 5. Realism: is 100/100 achievable for a small app?

- The docs show a 100/100 result for a clean PR-scope scan ([GitHub Actions setup](https://www.react.doctor/docs/ci-and-prs/github-actions-setup.md)). The rule-prompt docs aim at "Re-run until the scan is clean" ([How to fix issues](https://www.react.doctor/docs/getting-started/how-to-fix-issues.md)). For a small, new codebase written with the tool from day one, a full-project 100 is plausible. That is an inference. No primary source guarantees that zero findings maps to 100 under the current server formula.
- **Typical blockers, based on the docs and issue tracker:**
  - **False positives** are the most common issue type. Examples: [#1228](https://github.com/millionco/react-doctor/issues/1228) (`no-impure-state-updater`, "75 FPs / 77% of our errors"), [#1436](https://github.com/millionco/react-doctor/issues/1436) and [#2206](https://github.com/millionco/react-doctor/issues/2206) (memoization rules firing under React Compiler), [#1265](https://github.com/millionco/react-doctor/issues/1265) (`only-export-components`), and [#1444](https://github.com/millionco/react-doctor/issues/1444) (auto-imported JSX globals). Most are fixed quickly; about 44 issues were open at research time. Expect to need occasional suppressions or version pins.
  - **Supply-chain errors** on dependencies Socket.dev scores below 50, dev dependencies included by default (e.g. [#770](https://github.com/millionco/react-doctor/issues/770), a false warning for `@types/bun`).
  - **Complexity and duplication:** game UIs with big switch-heavy components (board or turn logic inside components) will trip `no-high-complexity-react-function` (above 15), and repeated JSX (similar panels and HUD rows) will trip `duplicate-jsx-subtree` ([React Maintainability](https://www.react.doctor/docs/overview/react-maintainability.md)).
  - **Accessibility rules** (93 in the index). Click handlers on non-interactive elements are common in board and dice UIs and are flagged by `click-events-have-key-events`, `control-has-associated-label` and similar rules ([rules index](https://www.react.doctor/prompts/rules.md)).
  - **Score not shown at all:** API unreachable, analysis incomplete ([#2018](https://github.com/millionco/react-doctor/issues/2018), large repos), or historically 413 errors on large payloads ([#300](https://github.com/millionco/react-doctor/issues/300)).
  - **Moving target:** new rules arrive with frequent releases (0.9.19 through 0.9.22 all came out between 2026-11-01 and 2026-11-02, [releases](https://github.com/millionco/react-doctor/releases)), and the server formula changes. Using `@latest` can turn a 100 into a 99 without any code change.

## 6. Gating

- **Exit codes:** `--blocking error|warning|none`. The CLI default is `error`. A blocking failure exits 1. `--warning-exit-code <2-255>` gives non-blocking warnings their own exit code ([cli/index.ts L264–272](https://github.com/millionco/react-doctor/blob/9791c32f61fb1477a4f8dd596ff80184ad26b2e3/packages/react-doctor/src/cli/index.ts#L264-L272), [warning-exit-code.md](https://github.com/millionco/react-doctor/blob/9791c32f61fb1477a4f8dd596ff80184ad26b2e3/docs/warning-exit-code.md)). The logic is in [resolve-scan-exit-code.ts](https://github.com/millionco/react-doctor/blob/9791c32f61fb1477a4f8dd596ff80184ad26b2e3/packages/react-doctor/src/cli/utils/resolve-scan-exit-code.ts): `none` gives 0; a lint hard failure gives 1; score-only mode or a degraded baseline gives 0; a blocking finding on the `ciFailure` surface gives 1. **The exit code never depends on the score.**
- **No score threshold.** There is no `--fail-under` or `min-score` option in the CLI ([CLI reference](https://www.react.doctor/docs/reference/cli-reference.md)) or in the Action inputs ([action.yml](https://github.com/millionco/react-doctor/blob/9791c32f61fb1477a4f8dd596ff80184ad26b2e3/action.yml)). (`supplyChain.minScore` is the Socket.dev per-dependency threshold, not the health score.) `--fail-on` is a deprecated alias for `--blocking`.
- **`--score`** prints only the number to stdout. If no score is available, it prints the reason to stderr and stdout stays empty ([finalize-inspect-result.ts L67–81](https://github.com/millionco/react-doctor/blob/9791c32f61fb1477a4f8dd596ff80184ad26b2e3/packages/react-doctor/src/cli/utils/finalize-inspect-result.ts#L67-L81)), and the exit code is 0 ([finalize-cli-scans.ts L95](https://github.com/millionco/react-doctor/blob/9791c32f61fb1477a4f8dd596ff80184ad26b2e3/packages/react-doctor/src/cli/utils/finalize-cli-scans.ts#L95)).
- **JSON:** `--json`, `--json-compact`, `--json-out <path>`. The report is versioned (schemaVersion 3). `summary.score` and `summary.scoreLabel` hold the worst project's score, and each project has `complete` and `analyzedFiles`. Errors still produce JSON with `ok: false` ([CLI reference](https://www.react.doctor/docs/reference/cli-reference.md), [json-report.md](https://github.com/millionco/react-doctor/blob/9791c32f61fb1477a4f8dd596ff80184ad26b2e3/docs/json-report.md), [summarize-diagnostics.ts](https://github.com/millionco/react-doctor/blob/9791c32f61fb1477a4f8dd596ff80184ad26b2e3/packages/core/src/summarize-diagnostics.ts)).
- **GitHub Action** `millionco/react-doctor@v2`. Inputs: `directory`, `project`, `scope` (default `changed` on PRs), `blocking` (default `none`), `comment`, `review-comments`, `commit-status`, `node-version`, `version` (default `latest`). Outputs: `score`, `total-issues`, `fixed-issues`, `error-count`, `warning-count`, `affected-files`. On non-PR events the job "never fails on findings" ([action.yml](https://github.com/millionco/react-doctor/blob/9791c32f61fb1477a4f8dd596ff80184ad26b2e3/action.yml), [GitHub Action reference](https://www.react.doctor/docs/reference/github-action-reference.md)). Use `fetch-depth: 0` for an accurate PR baseline ([GitHub Actions setup](https://www.react.doctor/docs/ci-and-prs/github-actions-setup.md)).
- **Other CI:** the CLI runs on GitLab, CircleCI, Jenkins and Buildkite ([Other CI providers](https://www.react.doctor/docs/ci-and-prs/other-ci-providers.md)).
- **Pre-commit:** `--staged` "scan[s] only staged (git index) files for pre-commit hooks … exits 0 when nothing is staged" ([cli/index.ts L259–262](https://github.com/millionco/react-doctor/blob/9791c32f61fb1477a4f8dd596ff80184ad26b2e3/packages/react-doctor/src/cli/index.ts#L259-L262)). The installer can add the hook to simple-git-hooks, ghooks, pre-commit, gitHooks, Lefthook and others ([install-git-hook-config-managers.ts](https://github.com/millionco/react-doctor/blob/9791c32f61fb1477a4f8dd596ff80184ad26b2e3/packages/react-doctor/src/cli/utils/install-git-hook-config-managers.ts)).
- **Example gate scripts.** These are my own, built on the documented flags.

  Strict and deterministic, sends nothing:

  ```bash
  npx -y react-doctor@0.9.22 . -y --scope full --blocking warning --no-score
  ```

  Literal score check (fails closed when no score is available):

  ```bash
  s="$(npx -y react-doctor@0.9.22 . -y --scope full --score)"; [ "$s" = "100" ] || { echo "React Doctor score: ${s:-unavailable}"; exit 1; }
  ```
